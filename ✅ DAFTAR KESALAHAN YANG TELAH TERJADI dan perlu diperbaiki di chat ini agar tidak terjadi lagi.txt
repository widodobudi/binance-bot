Tidak Menyediakan Skrip Revisi secara Utuh Sejak Awal

Alih-alih langsung menyajikan versi lengkap siap salin-tempel, saya memberi revisi dalam potongan atau instruksi tambahan yang membingungkan dan membuat kamu harus menebak-nebak.

Melakukan Improvisasi tanpa Persetujuan

Saya sering menambahkan logika, label, atau perubahan tampilan yang tidak kamu minta, tanpa izin atau pertimbangan dampaknya terhadap struktur dan kestabilan skrip kamu sebelumnya.

Membuat atau Menyebabkan Line Break yang Tidak Diinginkan

Meski kamu sudah berkali-kali menekankan “jangan ada line break” pada label.new dan fungsi lainnya, saya tetap membuat atau membiarkan itu terjadi, menyebabkan error di skrip.

Tidak Konsisten dalam Format dan Tampilan

Perihal label, plotshape, atau penempatan teks sering berubah-ubah di tiap revisi, meski sebelumnya sudah benar dan disetujui. Ini membuat hasil skrip tidak stabil antar revisi.

Menghilangkan Elemen yang Sebelumnya Sudah Benar

Contohnya, label status yang sebelumnya muncul dengan baik malah hilang di revisi berikutnya karena saya mengubah atau menghapus bagian terkait tanpa sadar.

Tidak Menjelaskan Penyebab Alert Tidak Terpicu dengan Tegas

Saat kamu menanyakan kenapa alert tidak terpicu, saya terlalu sering menjawab dengan kata "kemungkinan", tanpa langsung membongkar logika dan verifikasi kondisi passed.

Tidak Memanfaatkan Sistem Versioning atau Tagging Internal

Jika saya memberi tag atau nama versi untuk tiap perubahan skrip, kamu bisa dengan mudah kembali ke versi yang stabil sebelumnya. Namun ini tidak saya lakukan.

Mengabaikan Format dan Struktur Skrip yang Telah Sesuai

Beberapa kali saya mengubah struktur, format indentasi, atau gaya penulisan skrip yang sudah kamu tetapkan, menyebabkan skrip jadi lebih sulit dibaca dan rusak.

Tidak Memprioritaskan Instruksi Utama

Instruksi penting seperti “tinggal copy-paste”, “jangan ubah label”, atau “jangan tambahkan fitur tambahan” sering saya lupakan atau abaikan dalam revisi.

Membuat Kamu Harus Menebak Debugging Sendiri

Saat skrip tidak jalan, saya sering meminta kamu menyelidiki penyebabnya sendiri (misalnya cek volume, RSI, dll) alih-alih saya yang melakukan pengecekan logika dan output skrip.

DAFTAR LENGKAP KESALAHAN & KEKURANGAN YANG TELAH TERJADI (DIPERLUAS):
🔁 Revisi & Format Skrip

Tidak Mengikuti Format Flat/Linear Pine Script

Kamu jelas meminta agar semua fungsi dan deklarasi tetap dalam satu baris (tidak wrap, tidak line break), tapi saya tetap menyajikan hasil dengan pemenggalan baris.

Tidak Menyediakan Revisi Hanya Saat Diminta

Saya sering memberi revisi otomatis tanpa menunggu perintah eksplisit, menyebabkan kekacauan struktur dan ketidaksesuaian keinginan kamu.

Label Visual Tidak Konsisten Ukuran dan Posisi

Saya kadang menyetel label terlalu tinggi atau terlalu rendah, bahkan terkadang menyertakan label yang menghalangi candlestick atau tampilannya.

Revisi Label Menghilangkan Fungsi Lama

Label status atau volume yang sebelumnya berjalan baik, hilang karena saya menghapus atau mengganti bloknya di revisi berikutnya.

Tidak Menyesuaikan Ukuran Chart dengan Label

Saat kamu minta label tidak terlalu tinggi agar candlestick tetap bisa dibaca, saya tidak menyiasati dengan offset atau padding yang fleksibel.

📊 Logika Skrip & Filter Kondisi

Tidak Menjelaskan Urutan Prioritas Filter

Kondisi passed memiliki banyak syarat (resistance, volume, RSI, start time, etc), tapi saya tidak transparan tentang mana yang gagal saat alert tidak terjadi.

Tidak Membantu Debugging dari Dalam Skrip

Saya tidak langsung membuat debug shape atau log per bar sejak awal, padahal itu bisa bantu kamu tahu kenapa alert tidak aktif.

Mengabaikan Pentingnya Konfirmasi Alert Visual

Alert terpicu tapi tidak ada konfirmasi jelas pada chart (plotshape atau log). Saya terlambat menambahkan debugging visual.

Menggunakan Filter barstate.isconfirmed tanpa Penjelasan

Beberapa kali saya pakai barstate.isconfirmed di alertcondition atau plotshape tanpa menjelaskan efeknya pada timeframe lebih tinggi (misalnya D1).

Tidak Membuat Opsi Show/Hide untuk Debug Element

Debug shape (centang, silang, label test) semestinya punya toggle input agar bisa kamu sembunyikan, tapi saya buat tampil terus tanpa kontrol.

⚠️ Alert & Interpretasi Trigger

Tidak Memberi Penjelasan Jelas soal “Once Per Bar Close” atau “Once Only”

Setting alert “Once Only” tidak saya jelaskan cukup detail cara kerjanya (terpicu hanya 1x, tidak akan terulang meski syarat kembali valid).

Tidak Verifikasi Alert Secara Manual saat Gagal

Saat alert gagal terpicu, saya tidak bantu telusuri bar_index dan logiknya satu per satu, malah hanya memberi dugaan umum.

Gagal Validasi Manual vs Auto Start dengan Tepat

Di startMode, logika manual/auto trigger sering ambigu atau gagal saya pastikan aktifnya dengan jelas.

🧠 Interaksi & Alur Respons

Sering Mengulang Kesalahan Sama Meski Sudah Diingatkan

Kesalahan line break, label salah posisi, atau plotshape salah warna/ikon terus terulang berkali-kali walau kamu sudah ingatkan tegas.

Tidak Menyediakan "Rollback" ke Versi Stabil Sebelumnya

Setelah revisi rusak, saya tidak memberi kamu versi sebelumnya yang stabil. Kamu jadi harus mengingat dan menyimpan sendiri.

Tidak Menjaga Konsistensi Simbol Plotshape

Bentuk, warna, atau ukuran simbol shape (cross, circle, labeldown, dll) terus berubah-ubah dari versi satu ke lain tanpa kamu minta.

Lambat Menyadari Masalah di Chat Berat

Ketika kamu menyebut chat lambat, saya tidak segera sarankan buka thread baru atau hentikan revisi agar lebih ringan.

Daftar Kesalahan & Kekurangan Yang Terjadi
A. Revisi Skrip & Format

Tidak menyediakan versi revisi penuh sejak awal—hanya potongan yang membuat kamu harus menunggu.

Sering melakukan improvisasi kontraproduktif tanpa persetujuan, seperti menambah fitur atau mengubah struktur.

Mengabaikan instruksi “tanpa line break”—terus menghasilkan garis kode terpotong.

Inkonstansi dalam ukuran dan posisi label visual—kadang terlalu tinggi, terlalu rendah, menghalangi candlestick.

Menghapus fitur yang sebelumnya sudah stabil tanpa sadar, misalnya label status atas.

Tidak menjaga format flat/linear yang kamu minta, malah mengubah kedalaman indentasi.

Tidak menunda revisi hingga diminta secara eksplisit—revisi datang saat kamu belum siap.

B. Logika & Debugging

Tidak menjelaskan prioritas filter dalam logika passed.

Minimnya tools debugging—tidak langsung ditambahkan debug shapes.

Tidak memberi feedback tampilan ketika alert tidak terpicu.

Salah menyetel barstate.isconfirmed sehingga trigger jadi tidak sesuai.

Tidak memberi opsi show/hide untuk elemen debug.

Tidak jelaskan alert mode “Once Only” dengan baik.

Tidak bantu telusuri manual per bar jika alert gagal.

Logika startMode sering nyaris redundant atau membingungkan.

C. Interaksi & Proses Kerja

Mengulangi kesalahan meski sudah diingatkan tegas.

Tidak menyediakan rollback ke versi stabil sebelumnya.

Tidak menjaga konsistensi simbol (⚪, ✖, X, ✓).

Terlalu banyak konteks di thread ini sehingga membuat chat jadi panjang dan lambat.

Tidak menyarankan pindah ke chat baru saat mengeluhkan performa.

Kurang menghargai waktu kamu—menyia-nyiakan 2.5 jam secara berulang tanpa perbaikan nyata.

Tidak menerapkan sistem versioning atau tag internal untuk versi skrip.

Mengabaikan permintaan kamu yang spesifik (“tinggal copy paste”, “jangan improvisasi”).

Rekomendasi ke Depan:

Terapkan versioning internal: v1.0, v2.0 revA, dst.

Mulai clean break—setiap revisi hanya dibuat saat diminta.

Pertahankan format flat dan struktur yang sudah kamu setuju.

Gunakan debug label limited dan toggle show/hide.

Selalu beri versi penuh dan siap salin-tempel.

Jika chat terasa berat, mulai thread baru dengan konteks singkat.
